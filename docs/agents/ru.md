# Агенты, модели и лимиты

Выбирай Codex или Claude отдельно для daddy и воркеров. **Движок** — установленный модуль агента; **модель** и уровень усилий **effort** задают его работу. Нужные модули выбираются при [установке](../start/ru.md#модули).

## Подключить аккаунт

Команды авторизации выполняются на сервере с daddy.

### Codex

```bash
daddy auth agent codex
```

Пройди вход по коду устройства, затем вызови `daddy models --refresh`, чтобы увидеть каталог аккаунта.

### Claude

```bash
daddy auth agent claude
# Или используй существующий приватный файл с API-ключом:
daddy auth agent claude --token-file /private/anthropic-key
```

Скрытый ввод сохраняет ключ в `~/.tokens/anthropic`. Переменная `ANTHROPIC_API_KEY` в окружении сервиса имеет приоритет; `DADDYLOOP_CLAUDE_API_KEY_FILE` задаёт другой приватный файл. Доступ через API оплачивается отдельно от подписки Claude Pro/Max. Интеграция использует [официальный Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview).

## Где выполняются команды

По умолчанию Codex и Claude запускаются прямо на сервере под пользователем сервиса: `agentExecution: "host"`. Доступны сеть и DNS хоста, локальные сокеты и настроенные CLI. Дополнительных запросов разрешений от CLI нет; Bubblewrap и socat для обычного запуска не нужны. Существующие разговоры агентов тоже получают этот режим при следующем запуске.

У задач остаются отдельные рабочие копии, а приложение проверяет ревью и отправку результата. В режиме хоста роль координатора/ревьюера «только чтение» — правило работы агента, а не запрет записи на уровне ОС.

Для явно изолированной установки можно задать `agentExecution: "sandbox"` в конфиге сервера и перезапустить сервис. Этот режим ограничивает запись и сеть; Claude дополнительно нужны Bubblewrap, socat и разрешённые user namespaces. Режим передаётся через общий интерфейс адаптера и виден в `/api/status`.

## Выбрать модели

На сайте открой **Настройки сессии**, в CLI или Telegram — `/models`. Для daddy и воркеров отдельно выбираются движок, модель и effort. Дефолты можно задать командой:

```bash
daddy models --refresh
daddy agents defaults \
  --worker-engine codex --worker-model gpt-5.6-sol --worker-effort max \
  --daddy-engine codex --daddy-model gpt-6-astra --daddy-effort max
```

Названия выше — пример. Используй ID, которые вернул твой CLI. Codex читает `model/list`, Claude — `supportedModels()`, включая полученные алиасы и уровни усилий. Ответ кешируется на пять минут; обновление списка делает новый запрос. Доступ к модели провайдер проверяет при запуске хода.

Дефолты воркеров действуют на будущие задачи. Для смены daddy нужна свободная сессия. При смене движка создаётся новый нативный контекст, а разговор в daddyloop сохраняется. Ожидающие ходы используют зафиксированные профили. Подробнее: [задачи и пул](../tasks/ru.md), [контракт адаптера](../module-development/ru.md).

## Обновить CLI

Открой **Обновления CLI** на сайте или `/updates` в Telegram. У каждого установленного движка свои обновление и откат:

```bash
daddy updates --check
daddy runtime update --engine claude --yes
daddy runtime update --engine codex --yes
daddy runtime rollback --engine claude --yes
daddy runtime update-status
```

Подтверди показанные версии. До переключения daddy проверит контрольную сумму официального пакета, совместимость CLI и каталога, сохранённые профили, включая очередь. При ошибке останется выбранный CLI. Запущенные агенты закончат на своей версии; следующие ходы получат новую. На завершённую операцию бот отправляет одно сообщение.

Управляемые обновления работают на Linux x64/ARM64; Claude нужен glibc. Если CLI переопределён окружением, переключение отключается с указанием нужной настройки. Модуль без установщика предлагает инструкции релиза. Обновление CLI не обновляет адаптер или SDK daddyloop.

Выбрать другой исполняемый файл на сервере: `daddy runtime use /полный/путь/к/claude --engine claude` или `daddy runtime use bundled --engine codex`. Команда проверит CLI и перезапустит сервис, когда нет задач и обновлений в работе или очереди. [Сам сервис обновляется отдельно](../operations/ru.md).

## Лимиты

Панель над разговором показывает квоты каждого агента на компьютере и телефоне. Нажми на провайдера или период, чтобы открыть подробности и обновление данных. Неизвестные и устаревшие показания помечены. Дополнительные кредиты — отдельный платёжный баланс; ноль кредитов не означает, что включённая квота исчерпана. Нулевой баланс виден в подробностях, кроме случаев, когда провайдер сообщает только кредиты.

- **Codex:** читает квоты аккаунта из выбранного CLI и кеширует их на минуту. Сохраняются пришедшие периоды, время сброса, тариф и отдельные квоты моделей. Если тариф сообщает только неделю, будет только неделя; Spark и другие квоты показываются отдельно, когда они есть в ответе. Агенты одного аккаунта делят его квоту.
- **Claude:** показывает наблюдения `rate_limit_event`, которые считаются устаревшими через две минуты. Кнопка обновления не создаёт отсутствующий API квот. Токены и оценка стоимости последнего хода описывают активность, а не баланс аккаунта. Без данных остаток неизвестен. Сброс квоты этот адаптер не предоставляет.

```bash
daddy limits --refresh
daddy limits reset
daddy limits reset --request REQUEST_ID --yes
```

Подготовка сброса не тратит его. Для списания подтверди показанный запрос; при повторе используется тот же ID. Разговоры и файлы сохраняются. daddy не покупает кредиты и не расходует сбросы автоматически. Их доступное количество приходит от провайдера, а не из таблицы подписок.

## Если что-то не работает

`daddy doctor` проверяет включённые адаптеры без вызова модели. При ошибке авторизации проверь аккаунт или ключ на сервере; при пустом каталоге вызови `daddy models --refresh`. Ошибка протокола CLI или запуска оставляет работу незавершённой. Прочитай ошибку, исправь причину и продолжи; после несовместимого обновления CLI используй откат.
