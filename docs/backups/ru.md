# Сохрани работу папочки

Переносимый бэкап — архив `.tar.gz` с версией формата и SHA-256 файлов. Создание и восстановление записывают файлы потоком, соблюдают лимит размера и запас свободного места. В архиве твой код и переписка; храни его в доверенном месте.

## Создать и проверить

На исходной машине дождись важной работы или поставь нужные сессии на паузу, затем:

```bash
daddy down
daddy backup create ~/daddy-2026-09-11.tar.gz
daddy up
daddy backup inspect ~/daddy-2026-09-11.tar.gz
```

`create` требует остановленного сервиса и занимает ту же блокировку хоста, что `serve`. Сам он агентов не прерывает. Останови также другие процессы, меняющие исходные папки: если файл или состояние Git/Arc изменятся во время копирования, бэкап завершится ошибкой для повторного запуска. Существующий архив не перезаписывается. Команда печатает контрольную сумму, количество файлов, размер и предупреждения о восстановлении.

По умолчанию лимит распакованных данных — **20 ГиБ**. Для большего снимка после проверки диска добавь `--max-gib 40` к create, inspect и restore. Место нужно и для временной копии, и для итогового архива. Создание соблюдает `resources.minDiskGiB`; временные файлы удаляются только из собственных каталогов операции.

## Что переезжает

| Входит                                                                                 | Как восстанавливается                                                                       |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Сессии, задачи, сообщения, требования, решения, ревью, события и записанные результаты | Снимок SQLite; незавершённые задачи и сессии стоят на паузе                                 |
| Профили воркеров и daddy, язык, настройки ресурсов и кэша                              | `restored-config.json` и сохранённые предпочтения                                           |
| Объектные хранилища Git и рабочие копии daddyloop                                      | Файлы копируются; пути связанных worktree исправляются                                      |
| Локальные коммиты и ветки зарегистрированных Git-источников и разовых папок задач      | Git bundle, один на каждый источник                                                         |
| Отслеживаемые, staged и неигнорируемые новые файлы этих Git-источников                 | Отдельные папки восстановленных источников; индекс сохраняется                              |
| Артефакты приложения и сохранённые голосовые                                           | Копируются вместе с данными задач                                                           |
| Изменения задач в арендованных маунтах Arcadia                                         | База/HEAD, патчи коммитов, индекса и рабочих файлов, изменённые файлы в `recovery/arcadia/` |

Игнорируемые Git файлы исходных папок, например зависимости, не копируются. Рабочие копии воркеров сохраняются целиком, поэтому при необходимости сначала выполни безопасную очистку кэша. Отсутствующие исходные репозитории отмечаются в манифесте. Непереносимые симлинки, специальные файлы, превышение размера и неоднозначные переименования Arc вызывают явную ошибку, а не пропускаются молча.

Не переезжают: API/OAuth-ключи подключений daddyloop, браузерные токены, авторизация Telegram, состояние получения сообщений бота, Tailscale-идентичность, пути исполняемых файлов старой машины, установленные CLI/модели, живые процессы и аренды маунтов Arc. Модули на новой машине нужно установить заново. Сам код, комментарии или переписка могут содержать приватные данные; бэкап не является универсальным сканером секретов.

## Перенести на другую машину

Установи на новом хосте **ту же версию daddyloop** и нужные модули. Перенеси архив обычным защищённым способом. Останови пустой сервис перед выбором восстановленной конфигурации:

```bash
daddy down
daddy backup inspect ~/daddy-2026-09-11.tar.gz
daddy backup restore ~/daddy-2026-09-11.tar.gz --to ~/daddy-restored
export DADDYLOOP_CONFIG=~/daddy-restored/restored-config.json
daddy up
```

Каталог `--to` не должен существовать. Восстановление проверяет контрольные суммы и целостность базы до публикации результата. Данные не смешиваются с работающей установкой, существующие рабочие копии не перезаписываются.

По умолчанию Git-источники восстанавливаются в `~/daddy-restored/restored-sources/`; пути воркспейсов и задач указывают туда. Коммиты и незакоммиченные файлы можно проверить обычными командами. Для существующей папки на новом хосте передай соответствие:

```bash
daddy backup restore ~/daddy-2026-09-11.tar.gz \
  --to ~/daddy-restored \
  --map Work=/home/me/arcadia \
  --map App=/home/me/projects/app
```

Соответствие меняет ссылку на источник и ничего не записывает в существующий репозиторий. Сохранённые файлы Git-источника остаются в `restored-sources` для проверки. Разовую папку задачи можно сопоставить по старому полному пути: `--map /old/host/repo=/new/host/repo`. Для несопоставленного источника Arcadia нужен новый маунт.

Сервис, установленный командой `daddy up`, запоминает выбранный путь конфигурации. Для последующих CLI-команд сохрани `DADDYLOOP_CONFIG` в окружении или добавь export в настройки оболочки. Подключи аккаунты, Telegram и [доступ к сайту](../web/ru.md) на новой машине. Если используешь того же Telegram-бота, останови старую установку до привязки новой. Браузерам понадобится повторный вход.

## Контекст и незавершённая работа

Разговор с папочкой, требования, отчёты воркеров, опубликованные ревью и решения сохраняются. Внутренние ID сессий Codex/Claude очищаются: перенос ID не переносит историю внутри CLI. Следующий ход создаёт новый контекст агента по сохранённым материалам daddyloop. Незаписанные промежуточные размышления и история CLI вне daddyloop не восстанавливаются.

Открой приостановленную сессию, проверь доску и файлы, затем нажми **Продолжить** или отправь `/resume`. Сервис сверяет записанные нативные действия с провайдером; прерванный запрос не превращается в подтверждённый успех. Завершённые задачи остаются завершёнными. Восстановление не мержит PR и само не запускает бригаду повторно.

Для **Arcadia** изучи `recovery/arcadia/<task>/<role>/state.json`, возьми новый маунт через обычный lease-helper и восстанови базовую ревизию. Примени патчи коммитов, индекса и рабочих файлов в этом порядке, проверь сохранённые изменённые и новые файлы, затем сверь diff. После этого подключи задачу к восстановленной работе. Первый формат сохраняет эти материалы, но не воссоздаёт ветки Arc и не применяет патчи в живой маунт автоматически.

В первом формате нет встроенного расписания отправки в удалённое хранилище и шифрования. После проверки восстановления используй привычное защищённое хранилище и планировщик. Архив полезен, когда ты умеешь из него восстановиться.

Наборы инструкций сессии и снимки запусков включают сами тексты навыков и контрольные суммы. После восстановления не нужны прежняя папка навыка и скачивание из GitHub; указание источника сохраняется. Подробнее: [инструкции](../instructions/ru.md).

Библиотека пресетов входит целиком, вместе с копиями выбранных версий и галочками компонентов каждой сессии. Версия библиотеки может отличаться от версии в сессии; восстановление сохраняет обе.
