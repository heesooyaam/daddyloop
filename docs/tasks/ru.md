# Задачи и пул воркеров

Начни с `/new` в CLI, кнопки **Новая сессия** на сайте или `/new` у бота. Выбери воркспейс и опиши цель. Можно прислать GitHub issue, тикет Tracker или существующий PR в GitHub, GitLab или Arcadia.

```bash
daddy new --workspace App "https://github.com/acme/app/issues/42"
daddy sessions
daddy talk SESSION_ID "Возьми ещё https://github.com/acme/app/issues/43"
```

Сообщения в существующей сессии получает тот же daddy. Он читает требования, создаёт задачи, назначает воркеров и проверяет результат. Для независимого разговора используй `/new` или явно попроси создать новую сессию. В подключённой группе Telegram у неё появится отдельная тема.

## Размер пула

```bash
daddy pool SESSION_ID 3
```

По умолчанию один воркер, максимум — восемь. Команда запрашивает целевой размер, планировщик применяет его асинхронно. При уменьшении `3 → 1` занятые воркеры заканчивают **всю задачу**, включая ревью, исправления и CI; только затем лишние места освобождаются. Пауза и ожидание твоего ответа сохраняют место за задачей. Новый запрос размера заменяет предыдущий.

Лимиты памяти и процессов хоста могут разрешать меньше одновременных ходов, чем мест в пуле. Зависимости задают порядок, но не объединяют ветки. daddy сам решает, где полезен параллелизм: увеличение лимита не заставляет запускать лишних воркеров.

## Ревью и управление

Завершённые нативные ревью публикуются автоматически по умолчанию. Воркер получает опубликованный снимок замечаний. Незавершённое ревью, спор или устаревшая ревизия не превращаются в успешную передачу работы. Обязательные CI-проверки и человеческое принятие плана по-прежнему нужны для завершения. Автоматического merge нет.

Указания отправляй в основной чат daddy. Отчёты задач доступны для чтения; в них бывают явные действия: опубликовать ручное ревью, отправить готовую реализацию или принять план. Перед выполнением повторно проверяются точные ревизия и поколение задачи.

`/pause` приостанавливает сессию, `/resume` продолжает её. Закрытие CLI или браузера отключает только клиент. Остановка сервиса — другое действие: прерванная работа сохраняется и требует продолжения после проверки. Подробнее — [эксплуатация](../operations/ru.md).
