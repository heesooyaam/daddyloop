# Telegram: личка и темы группы

## Подключение бота

1. Создай отдельного бота через **@BotFather** и скопируй токен.
2. На машине с сервисом запусти `daddy telegram setup` и вставь токен в скрытый ввод. Можно передать `--token-file /приватный/путь`.
3. Открой выданную одноразовую ссылку и нажми **Start**. Бот привяжется к твоему Telegram-пользователю.

```bash
daddy telegram status
daddy telegram pair       # новая ссылка привязки
daddy telegram unpair    # отозвать привязку
```

Токен бота принадлежит этой установке сервиса. Выделенный бот не должен одновременно работать через чужой webhook или poller. Управлять задачами может только привязанный пользователь.

## Одна тема на сессию daddy

Создай в Telegram **супергруппу с включёнными темами**, добавь бота администратором и разреши управление темами. В личке бота отправь `/group` и выбери группу через системный выбор Telegram. Сервис проверит твоё участие и права бота. Группу создаёшь ты: бот не может молча создать её и добавить туда тебя.

Каждая сессия daddy получает свою тему. Пиши туда цели и тикеты; воркеры отчитываются daddy. `/new Другая задача` внутри темы создаёт отдельную сессию и тему. Обычное сообщение добавляет работу текущему daddy. Если результат создания темы неизвестен, следуй подсказке `/attach` от бота, чтобы не плодить дубликаты.

## Команды

| Где                              | Команды                                                                                                                                                                                                                 |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Личка и темы подключённых сессий | `/new`, `/sessions`, `/workspaces`, `/status`, `/pool`, `/models`, `/instructions`, `/skill`, `/presets`, `/preset`, `/repo`, `/limits`, `/pause`, `/resume`, `/notifications`, `/language en`, `/language ru`, `/help` |
| Личка                            | `/group`, `/updates`, `/web`                                                                                                                                                                                            |

`/web` выдаёт ссылку входа в браузер после настройки [постоянного HTTPS-доступа](../web/ru.md). Обновления CLI и подтверждения действий с аккаунтом остаются в личке. Работа продолжается, когда телефон и ноутбук офлайн.

Через `/notifications` выбирается тихий режим с итогами и вопросами, все обновления или отключение уведомлений. Голосовые идут в ту же сессию — см. [голос](../voice/ru.md).

В карточке сессии есть кнопка **Инструкции этой сессии**. `/instructions daddy <текст>` и `/instructions worker <текст>` задают отдельные промпты; `/skill <роль> <ссылка GitHub>` добавляет навык. Команды работают в личном разговоре и теме сессии в группе. Подробнее: [инструкции задачи](../instructions/ru.md).

`/presets` показывает общие пресеты. `/preset <название>` включает один в выбранном разговоре или теме. Другие сессии сохраняют свой выбор. Отдельные части выбираются в настройках сессии на сайте.

После успешного действия по кнопке бот отправляет новый ответ и удаляет нажатую карточку. При ошибке старая карточка остаётся для повтора; ответ в другой теме её не удаляет. Кнопки-ссылки открывают адрес напрямую — Telegram не сообщает боту об их нажатии.

Для Arcadia выбери Work, оставь автоматические копии включёнными и нажми **Начать сессию**. В карточке есть **Удалить сессию** с подтверждением: сервис сохранит результаты в архив и удалит копии. Подробнее — [Arcadia](../arcadia/ru.md).

Добавить репозиторий с телефона: **Воркспейсы → Добавить воркспейс → GitHub/GitLab**, затем пришли HTTPS/SSH-адрес и имя. Для Arcadia выбери её модуль и пришли путь к существующему маунту. `/cancel` отменяет добавление. Шаги привязаны к твоему чату или теме и действуют десять минут. `/repo URL` выбирает другой репозиторий на один запрос. [Источники воркспейсов и копии](../workspaces/ru.md).

## Один разговор в CLI, на сайте и в Telegram

После подключения группы через `/group` **каждая новая сессия** получает тему — в том числе созданная через `daddy new` или сайт. Нужна супергруппа с темами: у Telegram-канала тем нет. Боту нужны права создавать темы и управлять ими; после подключения вручную создавать их не придётся.

В теме видны отправленные сообщения пользователя с подписью `[user]` и реплики агента с `[daddy]`. Промежуточные реплики приходят целыми текстовыми блоками по мере готовности, затем приходит итоговый ответ. Команды, аргументы и результаты инструментов, stdout/stderr, рассуждения модели, служебный JSON и внутренние отчёты воркеров в эту ленту не попадают. Codex и Claude передают публичный текст через один интерфейс адаптера.

Ответь в теме — продолжится та же сессия на сервере. Сообщение из Telegram не дублируется в своей теме. Сообщение из лички боту попадёт в тему сессии. При переподключении досылаются сохранённые сообщения, для которых ещё нет записи об отправке в эту тему; уже доставленные сообщения не повторяются. Настройки уведомлений управляют личными оповещениями, а привязанная тема содержит сам разговор.

Агенты, история SQLite и подключение Telegram работают на сервере. Терминал на ноутбуке — ещё один клиент: его закрытие не останавливает работу и не отключает тему.
