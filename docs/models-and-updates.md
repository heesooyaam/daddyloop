# Языки, модели и версии CLI

В daddyloop основной разговор — с daddy. В текущей сессии `/models` настраивает daddy и будущих писателей; на сайте это «Настройки сессии». Уровни рассуждений и имена моделей берутся из Codex. В настройках моделей используются поля `writer` и `daddy`. Подробнее о новом интерфейсе: [CLI](terminal.md), [Telegram](telegram.md).

## Язык интерфейса

Поддерживаются **English** и **Русский**. Выбор на сайте, в TUI (`/language`) и боте (`/language en` / `/language ru`) сохраняется для рабочего пространства и применяется к клиентам при следующем обновлении состояния. `daddy language ru` сохраняет также настройку локального CLI. Для одного запуска: `daddy --language en`.

Тексты задач, описания тикетов, код и переписка не переводятся автоматически. Переключение языка не сбрасывает черновики и не перезапускает агентов. JSON-ключи CLI/API и имена команд остаются стабильными.

## Откуда берутся модели

daddyloop обращается к реально используемому `codex app-server` методом [`model/list`](https://learn.chatgpt.com/docs/app-server#list-models-modellist). CLI возвращает доступные модели и поддерживаемые уровни рассуждений. Продуктовый каталог не содержит списка названий моделей вручную; фиксированные имена встречаются только в примерах и offline fixtures.

Успешный ответ кешируется до пяти минут. При следующем запросе после истечения кеша каталог загружается заново. Принудительное обновление:

```bash
daddy models --refresh
```

В TUI: `/models refresh` или `/defaults refresh`. На сайте и в Telegram `/models` есть кнопка обновления. Рядом показываются источник, версия CLI и время получения. Список зависит от версии выбранного CLI, аккаунта и его доступа; новый релиз CLI иногда нужен для появления новой модели.

Модель и effort выбираются отдельно для автора и ревьюера. `/defaults` задаёт профили новых задач, `/models` — выбранной задачи; на сайте это **Agents & models**. Изменение профиля общего ревьюера применяется ко всей группе, когда его очередь свободна. Задания сохраняют профиль, с которым были поставлены в очередь. Режим делегирования `ultra` не предлагается для управляемого цикла с одним ревьюером.

**Рабочий движок сейчас только Codex.** Наличие Claude CLI на хосте не включает интеграцию Claude; его модели пока нельзя выбрать. В диагностике он помечен как неподдерживаемый движок.

## Обновления CLI

Сервис раз в шесть часов читает версию исполняемого файла и проверяет последнюю стабильную версию пакета в npm. Можно проверить сейчас:

```bash
daddy updates --check
daddy runtime
```

На сайте: **Updates / Обновления**, в TUI и Telegram: `/updates`. Отчёт показывает установленную и доступную версии, путь к файлу и происхождение — встроенный CLI или внешний. Ошибка сети отображается как неудавшаяся проверка, а не как подтверждение актуальности.

Если Telegram привязан и уведомления включены, для поддерживаемого движка приходит одно сообщение о новой доступной версии. Также сообщается о фактически изменившейся установленной версии. Повторные проверки не дублируют сообщение. Уведомления об обновлениях отключаются отдельно в экране Updates или боте. Установка требует явного подтверждения.

## Обновить Codex с телефона

В Telegram: **`/updates` → «Проверить сейчас» → «Обновить Codex» → «Подтвердить»**. В подтверждении показаны старая и конкретная новая версия; оно действует десять минут и только для привязанного пользователя. Сервер скачивает официальный Linux-пакет для своей архитектуры, проверяет SHA-512, версию, `initialize`, `model/list` и совместимость сохранённых профилей.

Обновление работает в фоне. Telegram и ноутбук можно закрыть: бот сообщит результат, а `/updates` покажет состояние. Новая копия устанавливается отдельно и выбирается атомарно, без перезапуска сервиса. Уже запущенный агент завершает текущий ход на прежнем CLI; следующий ход использует новый. Переписка, авторизация, модели автора и ревьюера сохраняются. Каталог моделей перечитывается после смены CLI.

После обновления появляется **«Откатить до …»** с отдельным подтверждением. Откат повторно проверяет прежний файл и его точную версию. Если внешний установщик удалил или заменил этот файл, daddyloop откажется переключать его вслепую. Ошибка скачивания или проверки сохраняет текущий CLI; повторная попытка требует нового подтверждения. После аварийного перезапуска незаконченная установка отмечается как прерванная, а уже записанное переключение восстанавливается из журнала.

То же через CLI, в том числе подключённый к удалённому daddyloop:

```bash
daddy runtime update             # показать конкретную версию
daddy runtime update --yes       # подтвердить и запустить на сервере
daddy runtime update-status      # состояние фоновой операции
daddy runtime rollback --yes     # вернуть предыдущий CLI
```

Повторный запуск `update --yes` получает свежий план и подтверждает напечатанную в нём версию. API: `POST /api/runtime/update/prepare` с `{"action":"install"}` или `{"action":"rollback"}`, затем `POST /api/runtime/update/confirm` с `{"id":"…"}`. Ответ `202` означает запуск, окончательный результат доступен через `GET /api/runtime/update`. Все маршруты требуют обычной авторизации daddyloop.

Обновляются только копии Codex, используемые daddyloop; глобальные npm-пакеты и установленный Claude не меняются. Установленные версии находятся в `DATA_DIR/runtimes/codex`; архивы и временные файлы удаляются после операции. Лимиты диска и памяти проверяются до и во время установки. Установленные CLI сохраняются и обычной очисткой кеша не удаляются.

## Встроенный или системный Codex

Релиз daddyloop содержит конкретную проверенную версию Codex. Обновление `codex` в системе не обновляет встроенную копию. Для независимого обновления CLI выбери его стабильный launcher на **сервере**:

```bash
daddy runtime use system
# либо свой абсолютный путь
daddy runtime use /home/you/.local/bin/codex
```

Команда проверяет, что CLI управляет именно локальной установкой, требует отсутствия работающих и ожидающих заданий, проверяет `initialize` и `model/list`, сохраняет путь и перезапускает сервис. При неудачном перезапуске настройка CLI откатывается. Автоматического ожидания завершения очереди нет: если она занята, команда завершится с понятной ошибкой.

Сохраняется стабильный путь ссылки, поэтому обновление её цели штатным updater не требует изменения daddyloop. Уже работающий процесс продолжает свой запуск; новая версия используется новыми процессами. Каталог при необходимости обнови принудительно.

Вернуться к копии из релиза:

```bash
daddy runtime use bundled
```

Проверка протокола при выборе CLI не выполняет платных модельных запросов и не проверяет каждый сценарий агентского запуска. Если новая версия меняет экспериментальный app-server протокол, может потребоваться обновление daddyloop. `DADDYLOOP_CODEX_BIN` в окружении сервиса имеет приоритет над конфигурацией и показывается как явное переопределение.
