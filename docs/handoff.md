# Работа с версией 0.4

Сервер и агенты работают на одной машине. CLI, сайт и телефон — клиенты; их отключение не останавливает сервис. Релиз установлен отдельно от исходников, данные и аккаунты сохраняются.

Начать задачу: `reviewctl` → `/new` → GitHub issue или Tracker тикет → путь к репозиторию на сервере. Обсуди решение с автором, затем `/implement`. Готовые ревью новых задач публикуются автоматически. `/defaults` задаёт модели новых задач, `/models` меняет выбранную задачу, `/child` добавляет автора с общим ревьюером.

Для текущего хоста выбраны GPT-5.6-Sol/max для автора и GPT-6-Astra/max для ревьюера. Лимит по умолчанию остаётся один активный агент; `/concurrency 2` разрешает независимым авторам работать вместе. Политики старых задач не меняются. [Примеры](tickets.md), [результаты ревью и проверок](review-v0.4.md).

Уведомления: колокольчик на сайте или `/notifications` в TUI. Режим «завершение и нужен мой ответ» позволяет смотреть результат в конце. Для доставки требуется привязанный Telegram-бот.

Действия владельца внешних аккаунтов:

1. Изменить видимость GitHub-репозитория на public, чтобы публичная команда установки могла скачать релиз.
2. Выполнить `reviewctl web tailscale` и войти в сеть, затем поставить Tailscale на телефон и получить ссылку через `reviewctl phone`. Альтернатива — свой постоянный HTTPS-прокси.
3. Создать бота через BotFather, выполнить `reviewctl telegram setup` и перейти по ссылке привязки. Затем `reviewctl notifications on --events attention`.
4. При необходимости подключить GitLab: `reviewctl auth gitlab`.

Проверить сервис: `reviewctl service status`, `reviewctl doctor`. Мониторинг диска и RAM остаётся включён; исходный Arcadia mount с пользовательскими изменениями сохраняется. Создание/публикация настоящего Arc PR не использовались для тестирования этого релиза.
