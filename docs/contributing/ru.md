# Как внести изменения

Используй Node 24 (см. `.nvmrc`) и отдельный checkout. Инварианты workflow и правила ресурсов записаны в `AGENTS.md` репозитория.

```bash
ONNXRUNTIME_NODE_INSTALL_CUDA=skip npm ci
npm run check
npm run format:check
npx playwright install chromium
npm run test:e2e
```

`check` проверяет типы, запускает офлайн-тесты, собирает приложение с чистым сгенерированным выводом и проверяет документацию. У браузерных тестов свои сервер, база, репозитории и данные аккаунта. Не превращай обычный тест в платный вызов модели или запись в настоящий PR. `scripts/smoke-codex.ts` делает реальные вызовы модели и запускается только намеренно.

В PR опиши изменение для пользователя, важные проверки и ограничения. Для модуля проверь общий контракт и адаптер протокола — см. [модули](../module-development/ru.md). Сохраняй точный Markdown, ревизии, поколения и восстановление неоднозначных операций.

## Документация всегда парная

Пиши простыми словами. Сначала дай общую картину и один понятный пример, затем объясни важные технические детали. В архитектуре покажи, кто кого вызывает, что передаёт, как меняется состояние и где проверяются инварианты. Не прячь это объяснение; дай ссылки на проверки в коде. Убирай повторы, сохраняя суть; объясняй термины и не перечисляй все внутренние поля.

Для каждой темы нужны `docs/<тема>/en.md` и `docs/<тема>/ru.md`. Обновляй обе страницы в одном PR. Проверка документации отклоняет отсутствующие пары языков, сломанные локальные ссылки, страницы вне оглавления и картинки без ссылок. При изменении навигации или первого запуска обновляй оглавление и оба корневых README.

Оригиналы лицензий лежат в `docs/licenses/`; поясняющие страницы всё равно двуязычные. Скриншоты — в `docs/media/`, на них ссылаются парные инструкции. Пользовательские данные, токены и приватные переписки бота не публикуются в медиа.

## Воспроизведение картинок

После сборки сними обе версии интерфейса:

```bash
DADDYLOOP_MEDIA_LOCALE=en node scripts/capture-daddy.mjs
DADDYLOOP_MEDIA_LOCALE=ru node scripts/capture-daddy.mjs
node scripts/capture-telegram.mjs
```

Браузер и Ink CLI работают на изолированных примерах: задачи, модели и квоты иллюстративные. Проверяются восстановление терминала и работа сервиса после отключения; телефонные кадры имеют размер 390 × 844. В `docs/media/` копируются только картинки, на которые ссылаются руководства или README; остальные проверочные кадры остаются временными. Главный кадр README — Мята. Карточки Telegram рисуются локально без обращения к Telegram.

После изменения текста, раскладки или цветов обновляй соответствующие скриншоты. Не публикуй токены, личные разговоры или содержимое корпоративных задач.

## Проверка реальных агентов

`scripts/smoke-codex.ts` и `scripts/smoke-claude.ts` запускаются намеренно и делают платные вызовы моделей. Для Claude после авторизации и настройки песочницы выполни `DADDYLOOP_LIVE_CLAUDE_TEST=1 npx tsx scripts/smoke-claude.ts`. Скрипт проверяет создание файла, продолжение контекста и вызов MCP во временной папке: два вызова с бюджетом $0.25 на каждый. Обычные тесты остаются офлайн.

## История релизов

Руководства описывают текущее поведение. Ревью и проверки конкретных изменений остаются в PR, история версий — в [GitHub Releases](https://github.com/heesooyaam/daddyloop/releases). Релизный workflow собирает описание из принятых PR; отдельного дневника релизов в `docs/` нет.
