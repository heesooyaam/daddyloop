# Как внести изменения

Используй Node 24 (см. `.nvmrc`) и отдельный checkout. Инварианты workflow и правила ресурсов записаны в `AGENTS.md` репозитория.

```bash
ONNXRUNTIME_NODE_INSTALL_CUDA=skip npm ci
npm run check
npm run format:check
npx playwright install chromium
npm run test:e2e
```

`check` проверяет типы, запускает офлайн-тесты, собирает приложение с чистым сгенерированным выводом и проверяет документацию. У браузерных тестов свои сервер, база, репозитории и данные аккаунта. Не превращай обычный тест в платный вызов модели или запись в настоящий PR. `scripts/smoke-codex.ts` делает реальные вызовы модели и запускается только намеренно.

В PR опиши изменение для пользователя, важные проверки и ограничения. Для модуля проверь общий контракт и адаптер протокола — см. [модули](../modules/ru.md). Сохраняй точный Markdown, ревизии, поколения и восстановление неоднозначных операций.

## Документация всегда парная

Для каждой темы нужны `docs/<тема>/en.md` и `docs/<тема>/ru.md`. Обновляй обе страницы в одном PR. Проверка документации отклоняет отсутствующие пары языков и сломанные локальные ссылки. При изменении навигации или первого запуска обновляй оглавление и оба корневых README.

Оригиналы лицензий лежат в `docs/licenses/`; поясняющие страницы всё равно двуязычные. Скриншоты — в `docs/media/`, на них ссылаются парные инструкции. Пользовательские данные, токены и приватные переписки бота не публикуются в медиа.

## Воспроизведение картинок

После production-сборки запусти `node scripts/capture-daddy.mjs`. Скрипт управляет настоящими браузерным и терминальным клиентами на изолированном примере. Он проверяет восстановление терминала и то, что отключение клиента не останавливает тестовый сервис. Подробнее — [медиа](../media-guide/ru.md).
