# Review 0.6.0

Full self-review covered managed Codex installation, authenticated API and paired Telegram controls, configuration activation, rollback, shutdown and crash recovery. No unresolved blocker or important finding remained after the fixes below. This was a self-review, not an independent agent review.

Confirmations pin the caller, source version and executable, target version, package URL and SHA-512 integrity. They expire and are consumed before any download begins. Only official stable Linux packages for the host architecture are accepted; callers cannot supply package URLs, commands or paths. Archive extraction sends named members through stdout into private files instead of allowing tar to choose filesystem destinations. Downloads and decompression have size/time limits, cancellation and resource checks.

Activation validates the candidate's reported version, initialize/model-list response and the saved model profiles. The original executable is re-probed before the atomic config change. Review identified a race between profile checking and this asynchronous probe; profile validation now runs after the probe, directly before switching. Config updates preserve concurrent changes to unrelated fields. A running turn captures its executable once; switching selections does not signal or replace its process. Late model-catalogue responses from the previous executable are fenced.

The durable activation journal distinguishes download/validation failures from a completed config replacement. Recovery recognizes a successfully selected candidate after a crash. Review also identified a cleanup hazard if a separate host-side configuration edit selected an in-progress candidate; cleanup now preserves any selected path within the operation directory, including resolved symlinks. Local `runtime use` refuses to race a managed update. Completed versions and the previous selection remain available; an externally removed or replaced rollback target is rejected after version/protocol validation.

Telegram remains responsive while installation runs. It checks the paired private chat and user before update callbacks, uses a separate confirmation namespace, and deduplicates result delivery durably. An uncertain send is retained rather than retried blindly. The result is also available through `/updates` and the authenticated update-status API.

Validation includes offline installer, controller, Telegram, API, catalogue and process tests; the existing workflow and browser regression suites also pass. Live Linux x64 checks installed official Codex 0.154.0, listed the six models available to the local account, performed an actual update and rollback through an isolated Reviewloop API with an unchanged service PID, and resumed one real conversation across Codex 0.153.4 → 0.154.0 using separate author/reviewer model profiles. The live conversation check exercised a dynamic tool, structured output and retained thread history; it did not publish comments or modify a repository. It does not establish compatibility with every future Codex protocol change.

Reviewed against `docs/architecture.md`, `docs/models-and-updates.md`, `docs/telegram.md`, the installed CLI and the [official Codex CLI documentation](https://learn.chatgpt.com/docs/codex/cli). Package layout and checksums were verified against the official npm package metadata and downloaded platform archive.
