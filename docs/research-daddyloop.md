# Research: Daddyloop

Дата: 2026-09-10.

## Контекст

Цель — один постоянный Daddy как собеседник и управляющий работой. Пользователь выбирает проект, отправляет задачи или ссылки на тикеты, настраивает размер пула писателей. Daddy уточняет требования, создаёт подзадачи и зависимости, поручает реализацию, проверяет результат и продолжает существующий цикл публикации/исправлений. Прямое общение пользователя с писателями закрывается; их отчёты остаются доступны для диагностики.

Ключевые файлы: `src/core/{engine,store,types,ticket-workflow}.ts`, `src/runtime/{worker,codex,workspaces,arc-workspaces}.ts`, `src/integrations/telegram.ts`, `src/server/{app,planning}.ts`, `src/ui/main.tsx`, `src/terminal/model.ts`. Проверенные исходные инварианты описаны в `docs/architecture.md`.

Прогресс:

- [x] Проверены ограничения Telegram и схемы команд агентов в официальной документации.

- [ ] Переименование в Daddyloop с совместимостью старой установки.

## Решения

**Проект — источник кода, сессия — работа Daddy, подзадача — отдельная рабочая копия.** Проект хранит путь к репозиторию на сервере, тип VCS, базовую ветку и относительную стартовую папку. С телефона выбираются названия проектов; пользователь не вводит абсолютный путь для каждого тикета. Существующие исходные рабочие копии сохраняются. Git-писатели используют управляемые worktrees, Arcadia — отдельно арендованные mounts с общим object store. Обнаружение Arcadia выполняется до любых Git-команд.

**Один Daddy и несколько писателей.** Существующая review group становится единицей Daddy-сессии. Для пользователя это один разговор. Внутри контексты управления и native review разделены: неопубликованные замечания и приватное ревью не попадают в контекст, который может давать инструкции писателям. На группу остаётся один постоянный контекст ревью; оба режима используют модель Daddy и сериализуются. Управляющие ходы получают отдельную устойчивую очередь и могут обслуживать пользователя, пока писатели работают. Число писателей — предел одновременной работы, по умолчанию 1. Зависимые задачи не запускаются до выполнения предшественников. Родительские инструкции и точные границы ревизий сохраняются.

**Только Daddy принимает пользовательские сообщения.** Он получает результаты работников и располагает ограниченными инструментами постановки задач, назначения работы, чтения состояния и передачи уточнений. У писателей нет инструментов управления пулом. Автономные продолжения запускаются событиями и имеют ограничение против повторов без прогресса. Незавершённый ход или потерянный ответ не превращаются в успех.

**Одна тема Telegram соответствует Daddy-сессии.** Внутри темы обсуждаются общий результат и её подзадачи. Привязка комнаты выполняется из личного чата владельца через Telegram chat picker; бот проверяет группу и права на управление темами. После привязки новые сессии получают темы автоматически. Контроль сообщений и кнопок ограничен привязанным пользователем и сохранённым соответствием темы/сессии. У создания темы нет ключа идемпотентности: неоднозначный ответ сохраняется для восстановления, тема не создаётся повторно вслепую.

**Названия и миграция.** Продукт, интерфейсы и основная команда становятся Daddyloop / `daddy`. Существующие данные, токены, управляемый Codex, systemd-установка и старые CLI-алиасы должны пережить обновление. Внутренние поля `author`/`reviewer` и маркеры ранее созданных native reviews сохраняются ради совместимости; они не задают пользовательскую модель общения.

## Источники

- [Telegram: выбор группы](https://core.telegram.org/bots/api#keyboardbuttonrequestchat) — группа выбирается пользователем, бот может получить запрошенные права.
- [Telegram: создание темы](https://core.telegram.org/bots/api#createforumtopic) — требуется право `can_manage_topics` в forum supergroup.
- [Claude: подходы к параллельной работе](https://code.claude.com/docs/en/agents) — различие между координацией агентов и изоляцией файлов через worktrees.
- [Claude: команды агентов](https://code.claude.com/docs/en/agent-teams) — общая очередь, руководитель и зависимости задач.
- `docs/architecture.md`, `docs/adr/0004-ticket-groups.md` — существующие гарантии native review, авторской рабочей копии и общей сессии ревьюера.

Открытое внешнее действие: владелец должен один раз выбрать или создать Telegram-группу с темами и предоставить боту необходимые права. Bot API не предоставляет метод создания группы от имени пользователя; это не будет подменяться автоматизацией личного аккаунта.
