# Модули и их интерфейсы

Установщик предлагает реально работающие модули:

| ID        | Назначение                                                | Дополнительная установка                                      |
| --------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| `codex`   | Запуск агентов, каталог моделей, квоты и обновления Codex | Codex CLI                                                     |
| `claude`  | Выполнение Claude, каталог моделей и события usage        | Claude CLI, Bubblewrap и socat                                |
| `github`  | Ревью, создание PR и GitHub issues                        | GitHub CLI для подключения аккаунта                           |
| `gitlab`  | Ревью и создание MR в GitLab                              | REST-адаптер, без GitLab CLI                                  |
| `arcadia` | Ревью и отправка PR в Arcadia, тикеты Tracker             | Использует уже установленные Arc, Arcanum и mount-инструменты |

Небольшие адаптеры и интерфейсы входят в приложение. Выбор модулей определяет, какие интеграции можно запускать; дополнительные CLI скачиваются только для выбранных пунктов. GitLab и Arcadia не устанавливают посторонний CLI. Аккаунты и корпоративные инструменты настраиваются отдельно. См. [установку](../start/ru.md) и [Arcadia](../arcadia/ru.md).

```bash
daddy modules list
# При установке:
# --modules codex,github,gitlab
```

Без `--yes` появляются галочки: стрелки перемещают выбор, пробел переключает, Enter запускает установку. `--yes` использует дефолты; текущая конфигурация может передать прежний выбор. Явный `--modules` заменяет его. Для смены набора заверши или приостанови работу, повтори установку с полным нужным списком и проверь `daddy modules list`. Разные наборы сохраняются как отдельные неизменяемые варианты установки. Рабочие данные и токены хранятся отдельно.

Модуль Claude поставляется: выбери `claude`, затем подключи API-ключ через `daddy auth agent claude`. См. [настройку Claude](../claude/ru.md).

## Интерфейс агента

[`AgentModule`](../../src/modules/contracts.ts) предоставляет runtime и каталог. [`AgentRegistry`](../../src/modules/agents/registry.ts) выбирает модуль для ходов задач и оркестратора по `profile.engine`. Модель и глубина рассуждений передаются модулю как данные.

- `AgentRuntime.run(AgentInput)` выполняет ход задачи.
- `SessionRuntime.runSession(SessionInput)` выполняет ход оркестратора.
- Во входе есть рабочая папка, сигнал отмены, инструменты, ограниченный callback вызова инструментов, события и callback сохранения сессии.
- Результат общий — `AgentResult`: статус, сводка, проверенная ревизия и идентификаторы проверок/споров.
- Каталог возвращает модели с указанием движка и проверяет его профили. Протокол, авторизация и получение моделей принадлежат движку.

Для планировщика идентификатор сессии непрозрачен и привязан к движку. Нельзя продолжить контекст другого движка. Явная смена движка начинает новый контекст и записывает прежние идентификаторы. Перед принятием результата workflow по-прежнему проверяет точные ревизию и поколение.

## Интерфейс репозитория

[`RepositoryModule`](../../src/modules/contracts.ts) предоставляет разбор PR, определение типа репозитория, нативный `ReviewProvider`, необязательный импорт тикетов и `SubmissionBackend`:

- `owner` проверяет нативную учётную запись.
- `prepare` проверяет и отправляет сохранённую реализацию.
- `create` создаёт PR/MR.
- `find` восстанавливает результат потерянного запроса по учётной записи, ветке/репозиторию и маркеру.

[`RepositoryRegistry`](../../src/modules/repositories/registry.ts) выбирает включённые модули. `TicketWorkflow` управляет сериализацией, outbox и проверками ревизии/поколения; REST/Arc-специфика лежит в реализациях модулей. Общие Git- и Arc-инструменты управляют изоляцией копий и защитой исходных папок.

## Добавление модуля через PR

1. Реализуй контракт в `src/modules/agents/` или `src/modules/repositories/`.
2. Зарегистрируй модуль в `index.ts` этой папки и добавь метаданные установщика в `src/modules/catalogue.ts`.
3. Если нужен дополнительный CLI, добавь проверяемый компонент релиза в `scripts/build-release.mjs`. Установщик читает метаданные пакета: отдельная shell-ветка под движок ему не нужна.
4. Для агента проверь отмену, продолжение сессии, некорректные результаты и область действия инструментов; для репозитория — точные ревизии, владельца, частичную публикацию и неоднозначные ответы.
5. Добавь обе страницы: `docs/<тема>/en.md` и `ru.md`. Обнови [оглавление](../index/ru.md) и запусти [проверки для PR](../contributing/ru.md).

Модули — доверенный код приложения, который проходит ревью и собирается вместе с релизом. Задача не может установить произвольный код или зарегистрировать себе backend.

Полный разбор интерфейсов usage, выполнения и репозиториев с примерами и тестами — в [разработке модулей](../module-development/ru.md).
